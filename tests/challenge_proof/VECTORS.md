# Candidate proof compatibility vectors

`vectors.json` is a fixed known-answer corpus produced independently by
`generate_vectors.cjs` using Node's built-in crypto/OpenSSL. The generator
imports neither Python nor the candidate implementation/canonicalizer. Its
small canonicalizer handles only the fixture's strings, nonnegative safe
integers, arrays, objects and null; it is not a general replacement for RFC 8785.
The cases cover ASCII, Unicode UTF-8 and the maximum safe binding revision.

Every seed is deliberately public test material and must never be used for
real custody. Public keys, canonical preimages, complete signed messages,
signatures and canonical proof wire bytes are committed for inspection.

From this code leg:

```sh
node tests/challenge_proof/generate_vectors.cjs
python -m pytest tests/challenge_proof/test_vectors.py -q
```

The first command compares independently regenerated bytes with the fixed
corpus and refuses drift. Maintainers can deliberately regenerate with
`--write`; ordinary tests never rewrite expected answers. Node 24.21.0 was
used for initial generation. Python CI needs no Node installation.

Tests consume the independent proof, compare the Python signer's exact
preimage/signature/wire output, and refuse independently signed wrong-domain
or changed-byte preimages, changed challenge digests and revoked bindings.
This is candidate interoperability evidence for two cryptographic software
stacks. It does not establish contract ratification, remote custody, live
registry integrity, MFA, human approval or consumer dependency acceptance.
